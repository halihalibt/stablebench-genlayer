# Deployment and verification

Only Stable Studionet is supported: chain ID **61999**, RPC `https://studio.genlayer.com/api`. The SDK `studionet` preset is pinned to `genlayer-js@1.1.8`. All deployment and write calls explicitly set `leaderOnly:false`; no test uses another chain or a single-leader shortcut.

From the repository root:

```sh
npm ci
npm test
npm run schema
npm run verify
```

`schema.json` is generated by the real GenVM schema endpoint. It is a GenLayer schema, not a Solidity ABI. Schema parsing alone does not prove execution. `npm run verify` is read-only: it independently re-fetches each recorded receipt, requires FINALIZED and the expected execution result, checks the actual rejection reason for negative tests, decodes calldata and compares sender/destination/method/arguments, verifies the deployed source bytes and re-reads the final state. It then recomputes domain-specific proof data offline. The offline recomputation is not a second network consensus.

`npm run live` deploys and runs real transaction acceptance, using three dedicated disposable signers funded by the official Studio test faucet. Keys are saved only in ignored `artifacts/test-signers.json` with mode 0600, and removed when acceptance completes. Each submitted hash is journaled before polling. An incomplete journal requires its original source and signers; it refuses replacement accounts or changed source. A completed journal is never repeated. Do not delete a pending journal to retry a write; inspect its existing hash. The runner is not a read-only check.

For another independent deployment use a separate clean checkout/journal. Preserve the Python dependency header, run the schema check, deploy with full consensus, wait for FINALIZED + SUCCESS and verify byte-exact source. Then update public `deployment.json` only with actually observed metadata. GenLayer Studio's Normal/Full Consensus deployment is also supported; constructor has no arguments.

## Actual calls

```sh
node scripts/call.mjs read get_protocol '[]'
```

`call.mjs write METHOD JSON_ARGS` uses your own authorized `CONTRACT_PRIVATE_KEY` environment variable, never a key in source or command arguments. It checks the pinned chain and source before submitting and prints the submitted hash before waiting for finality. It does not fund, replace or export your account. Use your wallet's normal secure environment provisioning; never commit keys or `.env`. The SDK writes attach zero value; no cash purchase, token transfer or paid external API is required by this primitive. Studionet and faucet availability are external dependencies, not an uptime promise.

After every successful write, read the relevant record using `latest-final`. A successful compilation can legitimately result in UNKNOWN; transaction success does not imply a usable semantic result. ACCEPTED is an intermediate transaction state, never the final acceptance criterion. A CLI timeout does not cancel a pending transaction.
